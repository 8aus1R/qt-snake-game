# Qt 贪吃蛇

这是我在面向对象开发综合实训中用 C++ 和 Qt Widgets 写的贪吃蛇。做这个项目时，我想把游戏里的不同事情交给不同的类处理：蛇负责移动，棋盘负责规则，窗口负责显示和接收按键。这样改游戏规则时，不用把所有代码都堆在界面里。

## 游戏内容

- 在 **20 × 20** 的棋盘上控制蛇移动，吃到食物加 1 分并增长一节。
- 食物随机出现在空格里，不会生成在蛇身上。
- 撞到边界或自己的身体后结束游戏；占满棋盘时显示胜利。
- 初始移动间隔为 **220 ms**，每吃到一颗食物缩短 **10 ms**，最快为 **100 ms**。
- 顶部显示分数、当前移动间隔和操作提示。

### 操作方式

| 按键 | 作用 |
| --- | --- |
| 方向键 | 控制移动方向 |
| Space | 暂停或继续；游戏结束后重新开始 |
| R | 游戏结束或胜利后重新开始 |

为了避免误操作，蛇不能直接掉头；同一个移动周期内也只接受一次有效转向。

## 面向对象设计

| 类 | 负责什么 |
| --- | --- |
| [`Snake`](snake.h) | 保存蛇身和方向，计算下一格、移动、增长，并限制非法转向 |
| [`Food`](food.h) | 保存食物在棋盘上的位置 |
| [`GameBoard`](gameboard.h) | 组合 `Snake` 和 `Food`，处理碰撞、吃食物、计分、胜负与重置 |
| [`GameWindow`](gamewindow.h) | 继承 `QWidget`，绘制界面、处理按键，并用 `QTimer` 驱动游戏 |

这些类各自保存自己的状态。比如窗口收到方向键后，只把方向交给 `GameBoard`；定时器触发时，`GameBoard` 推进一格，窗口再把当前状态画出来。`GameWindow` 重写了 `paintEvent()` 和 `keyPressEvent()`，这是项目里对 Qt 事件机制和继承的实际使用。

每次移动时，棋盘会先用 `Snake::nextHead()` 预测下一格并检查边界，再移动蛇身、检查是否撞到自己或吃到食物。这样撞墙时，蛇会停在最后一个合法位置。

## 运行项目

项目使用 **C++17** 和 **qmake（`.pro` 工程文件）**，在 Qt 5.12.12 的桌面环境下开发。

1. 用 Qt Creator 打开仓库根目录的 [`SnakeGame.pro`](SnakeGame.pro)。
2. 选择已配置的 Desktop Qt 5 kit 和 C++ 编译器。
3. 构建并运行项目。

仓库保存的是源码和工程文件，没有附带打包好的可执行程序或 Qt 运行库。

## 测试

[`tests/tst_gamecore.cpp`](tests/tst_gamecore.cpp) 使用 Qt Test 检查 `Snake` 的初始状态、移动、增长、反向转弯限制、单次移动内的转向限制，以及蛇身占格判断。

要运行这些测试，可以在 Qt Creator 中单独打开 [`tests/tests.pro`](tests/tests.pro)，选择相同的 Qt 5 kit，构建并运行测试项目。当前测试主要覆盖 `Snake`，不代表整个游戏的界面和全部规则都已自动化测试。

